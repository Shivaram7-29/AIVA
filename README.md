# PlacementAI 🚀

A comprehensive AI-powered platform for campus placement preparation, featuring an AI Resume Analyzer, AI Job Search Agent, Smart Application Agent, Aptitude Test Generator, and an Interactive AI Interviewer.

The landing page uses a VEX-style cinematic hero: fullscreen raw video background, liquid-glass navbar, character-by-character entrance animation, and white typography on a black/white/gray palette.

## ✨ Features
- **AI Resume Analysis**: Get professional feedback on your resume tailored for fresher roles.
- **AI Job Search Agent**: Upload your resume, let AI extract skills, search real job postings on Adzuna, and rank every job with evidence-based match scoring.
- **Smart Application Agent**: AI maps your resume to form fields, drafts custom answers, and generates cover letters.
- **Guarded Browser Application Agent**: Uses Playwright for common external forms, fills supported fields, uploads the real resume, pauses for CAPTCHA/login/MFA/missing information, and requires explicit confirmation before submission. Chromium is launched through Playwright's synchronous API on a dedicated worker thread for Windows/FastAPI compatibility.
- **Application Tracker**: Track every application from Saved to Offer.
- **Aptitude Tests**: Practice with TCS NQT-style questions generated by AI.
- **AI Interviewer**: Mock interview with a hyper-realistic AI avatar that speaks questions aloud.

## 🎨 VEX-Style Design
- **Landing hero**: fullscreen raw video (no overlay), liquid-glass navbar with `::before` gradient border, character-by-character heading animation, bottom-aligned content, right-side glass tag
- **Global font**: Inter (weights 300/400/500/600)
- **Palette**: black / white / gray-300 / gray-400 / white-20 only — no purple/cyan/neon
- **Liquid-glass** utility (`.liquid-glass`) defined in `src/index.css` per spec
- **Graceful video fallback**: if the remote video can't load, the hero falls back to a solid black background with a subtle vignette — the page never breaks

## 🛠️ Quick Start (Windows)

1.  Ensure you have [Node.js](https://nodejs.org/) and [Python](https://www.python.org/) installed.
2.  Double-click `RUN_PROJECT.bat` in the root folder.
3.  The script will:
    - Install frontend dependencies (`npm install`).
    - Create a Python virtual environment and install backend dependencies.
    - Install the Playwright Chromium browser.
    - Start the FastAPI backend server.
    - Start the Vite frontend development server.
4.  Open your browser to **http://localhost:5173**.

| `ADZUNA_APP_KEY` | yes | Free credentials from https://developer.adzuna.com/signup |

## 🩺 Error Handling Notes
- Missing `GROQ_API_KEY` → Job Search still returns deterministic matches; other AI-only features return **503** with an actionable message.
- Missing Adzuna credentials → job endpoints return **503**; total Adzuna failure → **502** with the API error text.
- Groq authentication, model, 413, timeout, malformed-JSON, and 429 causes are logged distinctly. Job Search falls back to deterministic matching rather than returning an empty result or an AI error.
- Missing Playwright or Chromium → browser-agent start returns **503** with an actionable installation command; manual external application remains available.

## 🤖 Guarded browser application agent

The existing preparation-only flow remains available. The optional Playwright
agent adds:

| Endpoint | Purpose |
|----------|---------|
| `POST /application/agent/start` | Opens the job URL, detects standard form fields, maps safe profile values, fills fields, and uploads the resume |
| `GET /application/agent/{session_id}` | Returns the current review state |
| `POST /application/agent/{session_id}/submit` | Accepts user-provided missing values and submits only when `confirm: true` |
| `POST /application/agent/{session_id}/continue-manually` | Pauses automation and returns the external URL |

Mapping uses labels, placeholders, names, ARIA labels, and nearby context.
Unknown candidate values remain missing and are never fabricated. The agent
supports common text inputs, textareas, selects, known radio/checkbox values,
and file uploads. It pauses instead of bypassing CAPTCHA, login, MFA/OTP,
anti-bot challenges, ambiguous controls, or unclear submission outcomes. A
successful click is recorded as `Submitted` only when a success indicator is
detected; otherwise the tracker records `Submitted - Verification Required` or
`Failed`. The browser is server-side headless automation. Playwright's
synchronous API runs on a dedicated single-thread worker so Windows Python
3.12/Uvicorn does not route the Playwright driver through the incompatible
default asyncio subprocess implementation. **Continue Manually** opens the
external page in the user's browser.

## 🔎 Job Search workflow and free-plan protection

The normal `/agent/run` workflow is intentionally small:

1. PyMuPDF extracts the resume text.
2. Python detects experience level, compacts the candidate profile, normalizes skills, and creates up to three Adzuna queries.
3. Adzuna results are deduplicated, location/seniority-filtered, and reduced to at most five candidate jobs.
4. One Groq request receives the compact resume evidence and compact job fields (title, company, location, and a short description excerpt).
5. Groq returns match scores, matched skills, missing required skills, evidence, and summaries. The server restores the original Adzuna URLs and metadata.

Every Groq request goes through a process-wide `GroqTokenBudget`. It estimates system prompt + input + requested completion tokens, reserves that amount in a rolling 60-second window, waits for the oldest reservation to expire when the configured budget is full, and never intentionally schedules a request over the default `6000` TPM application budget. Identical prompts are served from a short-lived in-memory cache, so repeating the same Job Search does not create duplicate Groq calls. Resume text is not persisted in that cache outside the running process.

The request guard uses the provider's `retry-after` or `x-ratelimit-reset-tokens` header for 429 retries, with exponential backoff only when those headers are unavailable. `x-ratelimit-remaining-tokens` is logged when the SDK exposes it. If the retry is exhausted, Job Search returns the deterministic matcher output with `_debug.ai_mode = "deterministic_fallback"`.

The deterministic fallback scores skill overlap, role/title similarity, experience compatibility, location compatibility, seniority, and explicitly required skills. Its evidence is taken from resume lines that contain the matched skill; it does not invent jobs, scores, or resume facts. AI remains the primary matcher whenever the Groq request succeeds.
